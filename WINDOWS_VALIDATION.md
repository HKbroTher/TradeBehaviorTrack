# Windows 10/11 validation

Use a standard user account and a non-sensitive test application. Close any application containing passwords or private documents. The current collector records **mouse aggregates only**. It is a controlled prototype, not a production privacy assurance for custom password controls.

1. Check out `feat/behavioral-guard-detector` on Windows and install Python 3.12 or newer. No Python packages are needed to run from source. Alternatively, find the `behavioral-guard-windows-prototypes` artifact from the latest successful **Windows validation** workflow; it contains a standalone mouse collector and desktop installer.
2. Open an ordinary app, such as Notepad, and run `BehavioralGuardSmoke.exe --consent --allow-exe notepad.exe --seconds 15` from the workflow artifact, or run `python smoke_windows.py --consent --allow-exe notepad.exe --seconds 15` from source. Use a normal, non-administrator terminal. Immediately switch to Notepad, then move and click the mouse there for several seconds. Confirm that approved samples and aggregate mouse metrics appear. Repeat while another app is foreground; approved samples should be zero. This smoke check writes no personal database.
3. In a controlled non-sensitive app, run `python capture_mouse.py --consent --allow-exe notepad.exe --window-seconds 60`. Move and click for at least one minute. Confirm a learning status appears and `%LOCALAPPDATA%\BehavioralGuard\behavior.sqlite3` is created. Do not use a password field for this check.
4. Open the desktop app. Confirm the data panel shows a window and learning date. Use **暂停监测** and check that the collector exits. Restart the collector with explicit consent if continuing.
5. Use **删除全部个人数据**. Confirm the dashboard becomes empty and the collector stops. The `stop-monitoring` marker may remain so an already running collector cannot resume without a new explicit launch.
6. Run `python -m unittest -v` and `python evaluate.py`. The simulation must suppress a single spike and alert after sustained change; its numbers do not estimate real-world accuracy.
7. Record Windows version, standard-user versus administrator status, foreground application, CPU and memory usage after 30 minutes, whether the tray persists after closing the window, and any failed step. Review modern password fields and locked-screen behavior separately before enabling keyboard collection.

This validation does **not** establish safety for custom password inputs, keyboard capture, device-switch detection, real-world false-alert rate, or clinical interpretation. These remain open requirements.
